# 六类业务问题怎样落到项目中

本表将需求中的业务问题转成可执行分析。所有方法和输出均为计划，尚未运行。公开历史数据可以支持证据和决策建议，不能保证部署效果。

| 原业务问题 | 数据与可执行分析 | 交付物及验收 | 可以说什么，不能说什么 |
| --- | --- | --- | --- |
| 哪些商品容易缺货 | M5 做商品/门店销量预测、波动和连续零销量调查；Retailrocket 补充 `available` 的时点关联 | 28 日预测误差、偏差、间歇销量标签；检查零销量、价格缺失和数据覆盖；与基线比较 | 可以定位需调查的商品；没有库存/供应事实，不能证明真实缺货、损失销量或最优补货量 |
| 哪些顾客行为相似 | Retailrocket 的近期行为、访问频率、加购与交易次数；若以后加入 Complete Journey，再做有金额含义的家庭 RFM | 可解释的行为分群、覆盖率、时间稳定性；分群参数仅用训练期估计 | visitor ID 不等于实名顾客；Retailrocket 缺可靠金额，不能把行为 RF 写成完整 RFM |
| 什么商品常被一起购买 | Retailrocket 交易事件按已审计交易键得到商品集合；可选 Complete Journey 篮子 | support/confidence/lift、最小共现数量、较晚时期验证、热门商品基线 | 同单关联是候选，不等于互补因果或推荐增量；交易事件不能全部当独立篮子 |
| 谁可能取消或放弃下单 | Retailrocket 建浏览/加购/购买事件路径，定义有完整观察窗口的未购代理指标；必要时做时间切分分类 | 明确分母、窗口和右删失；分群漏斗；PR-AUC、校准、基线与阈值成本 | 能研究观察窗口内未购；没有取消标签、结账步骤、退款记录，不能训练真实取消原因模型 |
| 哪些门店或流程异常 | M5 按商品/门店看季节基线偏离；Retailrocket 观察事件量与属性覆盖变化 | 候选异常表、数据故障排查和人工确认流程；展示告警量、误报审阅 | 没有人工真值时不能声称异常识别准确率；不同来源门店/访客编号不可混接 |
| 某次产品修改是否有效 | 针对商品页/可用性提示写实验方案；Criteo 修订版作为独立广告干预方法练习 | 随机化单位、主指标、护栏、成熟窗口、区间与停止规则；区分 treatment 与 exposure | 可评价发布样本内的广告实验信号及方法；不能说已经完成真实商品改版实验或上线提高转化 |

## 商品分析主线增加的实际问题

1. 销量贡献是否集中在少量 SKU？分类、门店和月份变化是否一致？
2. 相同销量水平下，哪些商品更波动或更间歇？ABC/XYZ 的阈值变化会怎样影响名单？
3. 商品价格变化与销量是否同向或反向变化？季节、节假日和在售范围是否构成替代解释？
4. 季节朴素预测和四周同星期均值，哪个更可靠？复杂模型是否值得新增维护成本？
5. 预测持续偏低的 SKU 是否应进入业务复核？成本、提前期和库存资料缺失时，决策需要补什么数据？

## 统一决策输出

每个分析保留“问题 → 数据与口径 → 结果 → 不确定性 → 建议行动 → 还需验证的证据”。行动包括优先调查、补充采集、开展实验或维持基线。观察关联和离线模型表现不直接转换成已实现收入、毛利或效率提升。
