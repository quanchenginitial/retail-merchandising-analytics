## SQL71 怎样定义路径

分析单位是 **一个访客编号与一个商品编号的组合**。同一访客浏览多个商品，会形成多个组合。每个有浏览记录的组合，从最早一次浏览出发：

| 阶段 | 进入条件 |
| --- | --- |
| VIEW | 至少有一次浏览，以最早浏览为起点 |
| VIEW_THEN_CART | 找到严格晚于该浏览的最早加购 |
| VIEW_THEN_CART_THEN_TRANSACTION | 再找到严格晚于该合格加购的最早交易 |

每个组合在各阶段最多计一次，反复浏览、加购或重复记录不会增加组合数。原始事件记录继续保留。**同一毫秒不能证明先后顺序**；如果之后还有符合条件的事件，仍可进入下一阶段。

输出包含以下 5 列：

- **stage**：路径阶段。
- **visitor_item_pairs**：达到该阶段的访客—商品组合数。
- **share_of_view_pairs_pct**：该阶段组合数 ÷ 全部有浏览的组合数。
- **step_rate_pct**：该阶段组合数 ÷ 上一阶段组合数。VIEW 没有上一阶段，所以为 NULL；分母为 0 时，比率也为 NULL。
- **check_status**：检查是否通过。

这里使用**整个已有观测期**，没有限定浏览后 24 小时等固定窗口。较早开始的组合可能有更长的后续观察时间，数据边界也可能截断前后行为；没有浏览记录的路径不进入本次分母。因此，“未观察到下一阶段”不能直接解释为顾客放弃购买，结果也不是会话、真实人数或已验证订单的转化率。
