## 为什么现在建立这张表

此前 rr_raw 层保留 CSV 的原始文本，便于追溯。现在把已经验证的类别编号和父类别编号放入明确的 BIGINT 整数列，让后续类别关联使用一致的字段类型，并能够检查键和引用关系。

本次新增 **rr_stg.category_tree**，包含两列：

| 字段 | 类型与保留规则 |
| --- | --- |
| categoryid | BIGINT 类别编号，验证必填和唯一性 |
| parentid | BIGINT 父类别编号；原有 25 个空父编号仍为 NULL |

参考表保持 1,669 行。转换需要满足严格的 ASCII 整数格式，并且转成整数后再转回文本必须与原文一致；空格、前导零等不会被自动修复。原始文本仍保留在 rr_raw.category_tree，转换后的表通过双向完整对账验证记录和重复次数。

25 个 NULL 父编号是根类别候选；检查直接父引用，并不能证明整个层级没有环路或每个节点都能到达根。环路、深度及根路径会在后续单独处理。

167 条未匹配的属性记录仍保留在原始属性表中。本次不为它们虚构类别、不补上猜测父节点，也不使用未来历史记录填补未知引用。
