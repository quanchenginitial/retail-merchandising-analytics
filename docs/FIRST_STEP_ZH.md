## SQL68 做什么

读取现有 **rr_stg.events** 与 **rr_core.item_state_intervals**，分别为 categoryid（类别）与 available（可用性）查找**起点不晚于事件时间的最近观察**，遵守包含起点、不含终点的 [from,to) 规则。

全部 **2,756,101 条事件记录**都会保留，包括此前确认的 460 条完全重复的额外记录；本步不去重，也不把事件记录数解释为独立用户数或订单数。

每一种属性都将事件划分为三类：

| 分类 | 含义 |
| --- | --- |
| MATCHED | 能找到事件发生时刻或此前的最近属性观察 |
| BEFORE_FIRST | 本次历史中有这个商品、这项属性的记录，但事件早于首条观察 |
| NO_HISTORY | 本次提供的历史中，没有这个商品、这项属性的观察 |

三类互斥，合计应回到全部事件记录数。**BEFORE_FIRST 不使用后来才出现的属性值反向补齐；未匹配也不等于不可用或缺货。** 类别属性匹配只表示找到一条类别值记录，本步尚不核对它能否关联类别树。

报告还展示 open_tail_match_rows：匹配到了末尾无后续记录的观察。这是 **MATCHED 的子集，不是第四类**，不能再与前三类相加。本步未设置属性年龄或新鲜度截止；找到最后记录的值不等于确认它在现实中仍然有效，更不代表库存数量。
