## 继续使用相同窗口，改用商品销量排序

**2016-01-26 至 2016-04-24，含首尾 90 天、全部 10 家门店。** 先将同一商品在各店的销量加总，再按销量从高到低排序；销量相同时按商品编号升序确定顺序。

这次衡量的是销量件数集中度，不是金额或利润集中度，也还没有分配 A/B/C 标签。先核对集中度，有助于避免机械套用“20% 商品必然贡献 80% 销量”。

## 八行分别看什么

| segment | 意义 |
| --- | --- |
| TOP_10 / TOP_50 / TOP_100 | 正销量商品中排名前 10 / 50 / 100 个商品 |
| REACH_80_PCT | 按销量排序后，累计达到或超过总销量 80% 所需的最少商品前缀 |
| REACH_95_PCT | 同理，累计达到或超过总销量 95% 的最少商品前缀 |
| ALL_POSITIVE | 窗口内有销量的所有商品 |
| ZERO_SALES | 窗口内总销量为 0 的商品 |
| ALL_PRODUCTS | 全部来源商品，包含零销量商品 |

**这些范围相互重叠，不能逐行相加。** 只有 ALL_POSITIVE 加 ZERO_SALES 才刚好组成 ALL_PRODUCTS。例如前 10 个商品已包含在前 50 个商品中。

`sku_share_pct` = 这一范围的商品数 ÷ 全部 3,049 个来源商品数；`unit_share_pct` = 这一范围的销量 ÷ 同窗口总销量 3,767,196 件。累计阈值包含跨过阈值的最后一个商品，因此结果略高于 80%/95% 是正确的。计算成员使用精确整数，显示才四舍五入。
