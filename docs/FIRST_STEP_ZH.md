# 当前一步：比较不同商品部门的预测误差

更新日期：2026-10-29（Australia/Sydney）。

**这一步为了什么：检查全量预测的优势是否在不同商品部门中都成立，并识别各部门整体偏高估还是偏低估。** 这会帮助我们确定后续分析应关注的业务范围。

SQL40 的 **6 行、12 列全部 PASS**，与独立预检一致。四周同星期均值的 MAE 改善覆盖率约为 54%–56%，RMSSE 约为 72%–76%；六个中位差值均为负，同时仍有平局和一周重复法更好的序列。

## 本步保留全部部门

不挑选表现有利的部门。每个开发窗口保留全部 **7 个商品部门、10 家门店**，三个窗口共输出 **21 行**。每行同时展示两种方法，便于直接比较。部门编码来自原始数据，不能自行推测其具体商品含义。

| 字段 | 读取方式 |
| --- | --- |
| series_count | 本部门的商品门店序列数，不是独立商品数 |
| snaive7_mae / weekday4_mae | 两种方法平均每个商品门店每天预测错多少件，越低越好 |
| mae_delta | 四周均值 MAE − 一周重复法 MAE，负数表示四周均值更好 |
| snaive7_mean_error / weekday4_mean_error | 平均“预测 − 实际”；负数表示低估，正数表示高估 |
| snaive7_macro_rmsse / weekday4_macro_rmsse | 对有效序列分别计算 RMSSE，再取平均 |
| rmsse_delta | 四周均值 RMSSE − 一周重复法 RMSSE，负数表示四周均值更好 |
| rmsse_valid_series / rmsse_undefined_series | 两种方法共享的 RMSSE 有效与未定义数量 |

**误差差值为负**与**平均偏差为负**含义不同：前者表示四周均值误差较低，后者只表示整体低估。部门销量规模不同，比较两种方法时应先在同一部门、同一窗口内对照。

## 核对输出

每个窗口应有 7 行，`series_count` 合计 **30,490**。每行 RMSSE 有效数加未定义数应等于该部门序列数。首窗全部部门合计 **30,480** 条有效、**10** 条未定义，后两窗均为 **30,490** 条有效、0 条未定义。

独立预检中，首窗的 10 条未定义序列分别归属 **FOODS_3：2 条、HOUSEHOLD_1：8 条**，其余部门与窗口均为 0。这是训练期尺度覆盖差异，检查状态仍应为 PASS。

七个部门规模不同，不能简单平均它们的指标来还原全量结果：MAE 和平均偏差按全部序列数加权，RMSSE 按有效序列数加权。差值用未四舍五入的指标计算，显示时才保留六位小数，因此末位可能与直接相减屏幕数字略有不同。

本步检查部门均值，不能据此推断部门内每个商品或门店都改善。最终留出期的实际销量仍不读取、不评分，最终模型尚未选择。
