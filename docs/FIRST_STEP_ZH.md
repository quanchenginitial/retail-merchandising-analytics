## 为什么还要检查完整层级

即使每个父编号都能在表中找到，仍可能出现“甲的父级是乙，乙的父级又是甲”的循环。这样的结构不能沿父链到达根，会影响按层级归类或汇总。因此，检查直接父引用之后，还需要检查完整路径。

SQL61 从父编号为 NULL 的根节点开始遍历，根深度定义为 **0**，每经过一条父子边增加 1。在编号唯一、非空且父引用完整的前提下，检查是否覆盖全部 1,669 个类别，有无重复访问或被深度上限截断的边，以及有多少类别受环影响。

**受环影响类别**包括自身处于环中的类别，以及沿父链最终进入环的类别；它不等于环成员数量。环归因要求输入前提成立，且遍历没有重复或被截断；此时非零数量虽会使无环控制 FAIL，仍是可解释的诊断。下面四项 INFO 观察则需要全部控制通过。

本步还输出四项观察：

| 观察 | 含义 |
| --- | --- |
| max_root_depth | 以根为深度 0 的最大深度 |
| leaf_nodes | 没有子类别的节点数 |
| branching_nodes | 至少有两个子类别的节点数 |
| max_children_per_node | 单个节点最多有多少直接子类别 |

这些是结构观察，expected 为 NULL，不预设必须等于 0。最大深度等具体值以本步实际报告为准。类别编号仍是匿名标识，本步不推断它们的业务名称，也不把类别树检查当作商品行为关联已经完成。
