**这一步为了什么：把上一张表中重叠的累计范围转换成互斥的商品标签，保存下来，供后续与 XYZ 销量波动性结合分析。**

你的 SQL20 截图已验收：8 行全部 PASS，累计达到 80% 销量需要 1,135 个商品，达到 95% 需要 2,103 个；共有 3,045 个正销量商品和 4 个零销量商品。见 [集中度验收](PRODUCT_UNIT_CONCENTRATION_VALIDATION.md)。

## 本次固定口径

继续使用 **2016-01-26 至 2016-04-24，共 90 天、全部 10 家门店**。先汇总每个商品在所有门店的销量，再将全部类别的商品放进同一队列，按销量降序、商品编号升序排列。

这是**按销量件数划分的全局 ABC**，不是按金额、利润、单个门店或类别内部划分。A 只表示这一口径下贡献较高的销量群体，不能单凭标签决定补货或下架。

## 四组如何划分

| 分类 | 规则 |
| --- | --- |
| A | 从第一名开始，直到累计销量首次达到或超过 80%，包含跨过阈值的最后一个商品 |
| B | 从 A 之后继续，直到 A+B 的累计销量首次达到或超过 95% |
| C | 剩余的正销量商品 |
| ZERO_SALES | 窗口内总销量为 0 的商品，单独保留，不塞入 C |

每个商品只属于一组，四组相加应还原全部 3,049 个商品和 3,767,196 件销量。A 与上一张表的 REACH_80_PCT 对应，A+B 与 REACH_95_PCT 对应。

代码用“当前商品加入前的累计销量”作精确整数比较，分类不依赖显示四舍五入后的百分比。跨阈值的商品属于较前一组，因此 A 的实际贡献可以略高于 80%。某些数据中某组可以为空；例如第一个商品已经贡献超过 95%，B 组就为空。

## 这次会保存什么

新增 `mart.m5_product_abc_90d`，每个商品一行，共 3,049 行、9 列，保存商品/部门/类别、窗口起止日期、销量、正销量排名、累计销量和 ABC 标签。零销量商品的排名与累计销量为空。日销量来源表保持原样。

这是一张固定窗口的分类快照，不是自动更新结果，也不表示 ABC 阈值敏感性已经完成。
