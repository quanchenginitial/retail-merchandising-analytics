SQL37 的 **6 行、12 列全部 PASS**，与独立预检一致。四周均值在三个窗口的 MAE 改善覆盖率为 **54.1667%、50.0000%、67.5926%**，RMSSE 改善覆盖率为 **72.6852%、65.7407%、80.5556%**。平均与中位差值均为负。第二个窗口 MAE 恰好有一半商品改善，另有 14 件持平、94 件变差。

## 这次扩大了什么

| 范围 | 商品门店序列数 |
| --- | ---: |
| 原试点：FOODS_1 / CA_1 | 216 |
| 本步：3,049 件商品 × 10 家门店 | 30,490 |

一件商品在十家门店各有一条销量序列，所以 30,490 不是不同商品的数量。两种方法、四个起点、未来 28 天，共产生 **30,490 × 2 × 4 × 28 = 6,829,760 条预测**。

方法保持原样：SNAIVE7 重复最近七天；WEEKDAY4 使用过去四次同星期几销量的均值，并保留小数。所有商品门店组合都参与，包括零销量记录。

两种方法最多需要每个起点最近 28 天输入。四个窗口合计 **112 天、3,414,880 条输入记录**，覆盖 2016-01-04 至 2016-04-24。本步核对这些输入，后续 RMSSE 评分还需要更长历史。最终留出期仍只生成预测，不用它的实际销量评分。

## 八行结果怎么读

四个起点各有 SNAIVE7、WEEKDAY4 两行。每行应有 **30,490 条序列、853,720 条预测**。

| 字段 | 含义 |
| --- | --- |
| input_days / input_units | 本方法使用的最近天数及对应历史销量总量：SNAIVE7 为 7 天，WEEKDAY4 为 28 天 |
| predicted_units | 该起点未来 28 天的预测销量总量 |
| zero_forecast_rows | 预测值为零的位置数 |
| fractional_forecast_rows | 预测值含小数的位置数；SNAIVE7 应为零 |

核对两个关系：**SNAIVE7 预测总量 = 最近 7 天销量 × 4；WEEKDAY4 预测总量 = 最近 28 天销量。** 这些是公式正确性的核对，不能据此判断预测准确度。
