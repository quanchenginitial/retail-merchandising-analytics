## 价格关联部分已验收

SQL49 的 14 行、12 列共 168 个结果值均匹配，14 个 PASS 完整可见。SQL44–49 的价格关联描述性里程碑已完成；异常分析及整个项目仍未完成。见 [本次验收](../data/week_department_price_contrasts_learner_acceptance.json) 和 [完整价格分析小结](STAGE06_PRICE_ASSOCIATION_FINDINGS.md)。

可以保留的主要发现：

- 335,374 次两端有价格的比较中，仅 3,796 次发生价格变化，约 1.13%；样本支持很不均衡。
- 整体涨价组和降价组的平均销量变化均为正，但按周、按部门拆开后，方向并不总一致。
- 同周同部门比较中，FOODS_1 涨价、降价组的加权变化差分别为 −0.531370、−1.376188 件，尽管有 8/10 和 9/10 个可比较周为正差。正差周数不能替代对变化幅度和样本权重的分析。
- FOODS_3 两种方向的变化差均为正；HOBBIES_2 降价组却只有 4 次比较，不能据小样本作广泛定价判断。

这些结果帮助确定需要调查的商品组合、时间和数据缺口。它们不能证明涨价或降价的因果效果，也不能计算实际促销收益。后续仍需要促销曝光、交易折扣、库存与在售状态等资料来区分可能解释。

## 下一步为什么先检查参考数据

要调查销量突增、突降或突然归零，需要先明确当前销量与什么比较。这里使用 **同一商品门店组合此前四个完整周的实际平均销量**，作为简单的历史参考。它不是“正常需求”的真值，也不改变此前已验收的日级预测模型和最终评估。

仍使用已建立的十二周数据：前四周（2016-01-30 至 2016-02-26）提供初始历史；后八周（2016-02-27 至 2016-04-22）是待筛查窗口。每个当前周只能使用此前四周，不能把当前周或未来周放进参考值。过去的零销量、价格缺失记录都保留。

每周有 30,490 个商品门店组合，八周合计 243,920 个待筛查位置。SQL50 只检查这些位置的覆盖、历史长度与汇总，**本次不输出异常标签或候选数量**。

## 怎样读结果

| 字段 | 含义 |
| --- | --- |
| retail_week / week_start | 八个待筛查周的编号与周开始日期 |
| series_count | 当周不同的商品门店组合数，应为 30,490 |
| scored_rows | 待筛查位置数，应为 30,490；字段名不表示已经生成异常评分或标签 |
| history_rows | 当周所有组合引用的历史周观察数，应为 30,490 × 4 = 121,960 |
| baseline_units | 各组合此前四周平均销量的合计，单位为件，保留两位小数 |
| observed_units | 当前周实际销量合计，单位为件 |
| zero_observed_rows | 当前周销量为零的位置数 |
| zero_baseline_rows | 此前四周销量合计为零的位置数 |
| priced_target_rows / missing_price_target_rows | 当前周有价或缺价的位置数，合计应等于 scored_rows |
| check_status | 数据覆盖、时间顺序与独立对账是否通过 |

baseline_units 已经除以四，与 observed_units 同为一个周的销量尺度；它不是四周销量总和。history_rows 是被引用的历史观察，滚动窗口会重复使用某些过去周，不能当作新增交易数量。汇总销量接近也不能证明每个商品门店组合都正常。

## 后续候选规则已固定，但本次不执行

未来 SQL51 将按固定优先顺序筛查：四个历史周均有销量而当前突然为零；相对历史均值至少翻倍且增加至少 7 件；相对历史均值至多一半且减少至少 7 件。突然为零还要求历史均值至少 7 件。边界均包含等号，类别互斥。

7 件/周对应平均每天一件，是本项目明示的初步筛查门槛，并非行业标准或经效果优化的阈值。此前四周全零时，当前至少 7 件可进入突增候选，只描述为零销量后的活动，不计算百分比增长。后来发现的候选周仍保留在后续历史均值中，不迭代剔除。

候选只是人工复核线索，不能直接称为真实异常、缺货、促销效果或数据错误；没有人工标签也不报告准确率。规则详见 [异常筛查协议](ANOMALY_SCREENING_PROTOCOL.md)，本步方法和预检见 [范围核验说明](ANOMALY_BASELINE_SCOPE_VALIDATION.md)。
