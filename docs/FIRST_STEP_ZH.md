# 当前一步：按固定规则生成销量异常候选

更新日期：2026-11-02（Australia/Sydney）。

**这一步为了什么：把销量变化转成需要人工复核的候选，帮助确定后续排查重点。**

## SQL50 已验收

截图的 8 行 × 12 列、共 96 个字段值及 8 个 PASS 均匹配冻结报告。每周 30,490 个商品门店组合、121,960 次历史周引用均正确；八周共 243,920 个待筛查位置。每个位置的参考值只使用同一组合此前四个完整周的实际平均销量，零销量也保留。见 [本次验收](../data/anomaly_baseline_scope_learner_acceptance.json) 和 [范围审计说明](ANOMALY_BASELINE_SCOPE_VALIDATION.md)。

这证明下一步的参考数据和覆盖范围符合协议；尚未证明哪些记录是真实异常。历史窗口彼此重叠，引用次数不是新增交易数量。

## SQL51 要做什么

沿用已固定的规则，对 2016-02-27 至 2016-04-22 的八周逐个分类。设当前周销量为 y，此前四周的平均销量为 μ：

| 类别 | 规则（均包含等号） | 用途 |
| --- | --- | --- |
| SUDDEN_ZERO | 当前为零，此前四周每周均有销量，且 μ ≥ 7 件 | 排查从持续有销量到突然归零的变化 |
| LARGE_INCREASE | 尚未入前类，y ≥ 2μ，且 y − μ ≥ 7 件 | 排查同时满足相对和绝对门槛的增加 |
| LARGE_DECREASE | 尚未入前类，y ≤ 0.5μ，且 μ − y ≥ 7 件 | 排查同时满足相对和绝对门槛的减少 |
| NONE | 未触发以上规则 | 保留其余观察，不能直接称为已证实正常 |

按表中顺序判定，每个位置只属于一类。例如，前四周各卖 8 件、当前卖 0 件，会进入 SUDDEN_ZERO，不重复计入 LARGE_DECREASE。前四周全为零时，当前 6 件为 NONE，7 件进入 LARGE_INCREASE；这只描述零销量后的活动，不计算从零增长的百分比。

7 件/周是本项目事先明示的初步门槛，约等于平均每天一件，并非行业标准或经效果优化的阈值。不会根据本次候选数量调整门槛。既往被标记的周仍按实际销量进入后续滚动历史。

## 怎样读结果

| 字段 | 含义 |
| --- | --- |
| target_rows / target_share_pct | 本类目标位置数及其占全部 243,920 个位置的比例；分母包括 NONE |
| distinct_series | 本类涉及的不同商品门店组合数；同一组合在不同周可能落入不同类，不能跨类相加 |
| baseline_units / observed_units | 本类历史平均销量的合计 / 当前实际销量的合计，单位均为件 |
| unit_difference | 当前实际合计减去历史参考合计，保留正负号；不是损失销量 |
| mean_unit_difference | 本类每个位置的平均件数差；TOTAL 按全部位置计算，不是类别均值的简单平均 |
| zero_observed_rows / zero_baseline_rows | 当前销量为零 / 四周历史合计为零的位置数 |
| missing_price_rows | 当前缺价的位置数；价格不参与候选判定，也不用于排除记录 |
| check_status | 输入、时间顺序、分类和汇总对账是否通过；PASS 不等于真实异常得到证实 |

四类 target_rows 应相加为 243,920；TOTAL 的 distinct_series 应为 30,490。各类百分比单独保留四位小数，显示值相加可能有极小舍入差。空类别也保留，其数量、比例和合计为零，平均差为 NULL。

## 后续如何使用

本步先了解候选规模，再对代表性记录检查其历史走势、季节与事件信息、价格和数据完整性。销量归零不能单凭这些数据判为缺货；增加或减少也不能直接归因于促销或调价。候选均值的正负由筛选规则决定，不能作为规则有效性的独立证据。

没有库存、在售状态和人工核实标签时，不报告真实异常率、识别准确率、缺货损失或业务节省金额。当前使用已探索过的历史窗口；过去数据构建基线并不让它成为新的未来测试。原有预测与价格关联结论保持不变。

规则见 [已冻结筛查协议](ANOMALY_SCREENING_PROTOCOL.md)，输出与验证约定见 [SQL51 输出协议](ANOMALY_CANDIDATES_PROTOCOL.md)。SQL51 用户验收、候选调查和完整项目交付仍未完成。
