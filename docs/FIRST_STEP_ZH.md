**这一步为了什么：建立“同一商品、同一门店、同一完整零售周”的销量和价格记录，为后续比较调价与销量变化做准备。**

SQL43 的两行、十二列已验收，均为 PASS。最终28天中，四周同星期均值法的 MAE 为1.103654、平均 RMSSE 为0.828159，相比一周重复法约降低11.28%和16.96%（由显示值估算）。它仍整体低估48,138件；这些是公开历史数据的基线比较结果，不是已经实现的库存或收入收益。见 [预测阶段总结](STAGE05_BASELINE_FORECAST_FINDINGS.md)。

## 为什么需要这张表

之前的商品周表把十家门店的销量合并了，而同一商品在不同门店可能有不同价格。要讨论价格与销量的关系，必须保留门店这一层，先汇总七天销量，再按商品、门店、零售周三个字段连接周价格。

SQL44 沿用 **2016-01-30至2016-04-22** 的十二个完整零售周，共84天。一行代表一个商品在一家门店的一周：**3,049商品 ×10店 ×12周 =365,880行**。这样既与前面的周销量分析保持同一窗口，又保留了门店价格差异。

本步只建立和核对数据，尚不计算价格弹性或促销效果。预测阶段的选型和最终结果保持不变。

## 核对哪些内容

每周应有 **30,490行**商品门店周记录、**213,430行**源日记录；TOTAL应为 **365,880行、2,561,160行日记录、3,536,539件**。新表按商品和周重新合并十家店后，也应逐行匹配原来的商品周表。

| 字段 | 含义 |
| --- | --- |
| series_week_rows | 商品门店周记录数，不是不同商品数 |
| zero_sales_series_weeks | 零销量周记录数，同一商品门店可在多个周重复计入 |
| priced_series_weeks | 能匹配到该商品、该门店、该周价格的记录数 |
| missing_price_series_weeks | 没有匹配价格的周记录数；缺失的是价格，保留NULL，不补0 |
| missing_price_positive_sales_weeks | 有销量却缺价的记录数，本次合同要求为0 |
| priced_units | 有价格记录覆盖的销量，应与units一致 |

“有价周数 +缺价周数”应等于全部周记录数。缺价格或零销量本身都不能直接证明缺货。
