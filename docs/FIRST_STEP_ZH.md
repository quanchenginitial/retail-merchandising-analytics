## 本步怎样检查

SQL59 继续使用同一批“精确未匹配”记录，不因为后续数值比较而改变群体。先统计不同原始商品编号、类别值、时间戳和两个来源文件的记录数，再检查数字形式的类别值能否与参考表形成候选关系。

| 诊断 | 本步口径 |
| --- | --- |
| 数值资格 | 只接受 ASCII 数字、且可放入非负 BIGINT 的文本；不先去空格，不修复文本 |
| 唯一数值参考 | 解析后相同数值仅对应一个不同的原始参考类别编号 |
| 歧义数值参考 | 同一数值对应多个不同的原始参考类别编号 |
| 无数值参考 | 该记录具备数值资格，但参考表没有对应数值 |

数值转换只用于本次诊断，原始字段保持不变。唯一候选不等于已批准的修复，无法匹配也不能说明来源为什么缺失。参考表自身的无资格行和歧义数值编号是另一统计范围，不能与未匹配记录数直接相加。此处也不完成全部属性键的类型转换碰撞检查。
