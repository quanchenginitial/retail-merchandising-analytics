## 为什么把映射保存成表

SQL61 回答了“层级是否成立”；SQL62 把可复用的结果保存下来，避免每次按根类别汇总都重新计算类别路径。

本次新增 **rr_core.dim_category**，每个类别一行，四个字段均为 BIGINT：

| 字段 | 含义 |
| --- | --- |
| categoryid | 本类别编号 |
| parentid | 直接父类别编号；根的父编号保持 NULL |
| root_categoryid | 沿父链到达的根类别编号；根指向自身 |
| depth | 到根的边数；根为 0，子节点比父节点多 1 |

表中保留 1,669 个类别、25 个根和已验收的最大深度 5。检查会核对每个类别的根、父子深度关系，以及全部两字段来源记录和四字段预期映射，避免仅凭总行数相同就接受结果。唯一性和非空是本次验证的数据条件，不是已经声明的数据库主键约束。

这是提供的静态类别参考映射，不是所有祖先关系的展开表，也不包含历史有效期或事件时点匹配。匿名类别编号的业务名称不会被猜测填入，167 条未匹配属性仍保留原样。
