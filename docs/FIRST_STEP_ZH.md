## 为什么下一步按周看

总候选数量还不能告诉我们复核工作是否集中在某些时间。SQL52 沿用 SQL51 的全部标签和阈值，把八周依次展开；每周都保留，即使该周没有候选。

同时分别汇总向上、向下偏离此前四周均值的件数。分别展示两种方向，是为了避免增加与减少相互抵消，也帮助区分“很多小变化”和“较少但幅度大的变化”。这些差值来自历史均值参考，不能当作缺货损失、增量收益或因果效果。

## 怎样读结果

| 字段 | 含义 |
| --- | --- |
| retail_week / week_start | 目标周编号与开始日期，覆盖 2016-02-27 至 2016-04-22 的八个完整周 |
| target_rows | 每周全部商品门店目标位置，应为 30,490 |
| sudden_zero_rows / large_increase_rows / large_decrease_rows | 三类候选各自的位置数，类别互斥 |
| none_rows | 未触发固定规则的位置数；不代表已证实正常 |
| candidate_rows | 三类候选之和 |
| candidate_share_pct | candidate_rows ÷ target_rows × 100；分母包括 NONE，保留四位小数 |
| upward_gap_units | 仅明显增加组的“当前销量 − 历史均值”合计 |
| downward_gap_units | 突然归零及明显减少组的“历史均值 − 当前销量”合计，显示为正数 |
| check_status | 分类覆盖、时间分组与汇总对账是否通过 |

八周 candidate_rows 应合计 12,347。向上差值合计应为 105,974.00 件，向下差值合计为 104,809.75 件。两者之差 1,164.25 件仅属于三类候选，**没有计入 NONE 的 9,894.00 件净差**，因此不等于全部目标的 11,058.25 件净差。不能把正数 downward_gap_units 解读为损失销量。
