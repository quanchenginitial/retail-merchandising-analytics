# 当前一步：给销量走势补充每周价格背景

更新日期：2026-10-29（Australia/Sydney）。

**这一步为了什么：在已知十家门店销量都增加之后，查看这段时期的价格记录是否也有变化，形成可核查的解释线索。** 这里先描述价格和销量的共同变化，不估计价格弹性，也不判定因果。

SQL31 的 11 行、11 列截图已验收，门店排序、空州汇总、各店数值及总量与预查一致。10 店后六周销量均高于前六周，总差额为 +2,606 件。

## 比较对象不变

仍自动选择已验收 A × Z 组中 90 天销量最高、同销量时商品编号升序的首个商品。ABC 选品窗口保持 **2016-01-26 至 2016-04-24**；本次展示 XYZ 的 **2016-01-30 至 2016-04-22**，12 个完整周。

每周保留全部 10 家门店，共 120 个“门店 × 周”位置。价格取该商品在该店该周公开的 sell_price，不用销量加权平均价替代原始价格。

## 本次结果怎么读

| 字段 | 含义 |
| --- | --- |
| item_id | 同一个被选中的商品 |
| week_start / week_end | 该完整周的开始与结束日期 |
| units | 该商品在全部门店的周销量，与已验收 SQL30 一致 |
| priced_stores / missing_price_stores | 该周有价格记录 / 没有价格记录的门店数，两者合计应为 10 |
| min_price_usd / max_price_usd | 该周有价格记录门店中的最低 / 最高公开周价格 |
| comparable_stores | 本周和紧邻上周都有价格的同一门店数量 |
| price_up_stores / price_down_stores | 上述可比门店中，本周价格高于 / 低于上周的数量 |
| check_status | 输入、价格键、覆盖及销量对账通过为 PASS |

首周在本次窗口内没有上一周，因此 comparable_stores、price_up_stores、price_down_stores 三列应为 NULL。查询不会为了比较首周而引入窗口外数据。

从第二周起，只比较连续两周都有价格的同一家店；缺价之后重新出现价格时，如果紧邻上一周仍缺价，就不能与更早的价格比较。如果 comparable_stores 为 0，涨价和降价数也为 0，但这表示没有可比对，不能据此认定价格未变。可比门店中的不变价数量等于 comparable_stores 减去涨价数和降价数。

## 需要区分的情形

- 没有价格记录时保留 NULL；不能把未知价格写成 0。
- 如果某个有正销量的“商品 × 门店 × 周”缺价，查询报错；零销量位置缺价可以保留为未知。
- 若某周所有门店都缺价，该周价格上下限为 NULL；销量记录依然保留。
- 合法空 A × Z 组显示一行 EMPTY，其余商品、周、价格指标为 NULL。本数据应选中商品，出现 EMPTY 或错误时请保留输出发回。

助手独立预查通过：120 条原始价格记录与 12 行全部 12 字段核对一致，36 个针对性测试通过。当前数据每周 10 店都有价格、缺价数为 0，整体价格范围为 2.00–2.68 美元；这个范围不是所有门店的统一调价幅度。10 店各有 11 次相邻周比较，共 110 次，其中 2 次上涨、1 次下降、107 次不变。

完整方法和预查见 [价格背景验证说明](AZ_LEADING_PRODUCT_PRICE_CONTEXT_VALIDATION.md)。**助手预查与用户本地执行分开记录，SQL32 仍待你的截图验收。** 公开证据只保留汇总与指纹，实际商品门店价格和逐周结果留在本地。

价格下降不自动等于促销，缺价不自动等于缺货；门店价格范围的变化也可能受有价门店集合变化影响。先结合覆盖数和同店可比数量读表，再讨论观察到的现象。
